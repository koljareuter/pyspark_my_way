# Interchannel Correction Bugfix

**Date:** 2026-09-23  
**Affected config option:** `[detector] interchannel_correct = True`  
**Symptom:** Every OB fails at "Running detector corrections" with a bare
`error: cannot open file [KMOS*.fits]` line in the main log and no science
cubes produced.

---

## Background

The H2RG detector in KMOS has 32 independent readout channels, each covering
64 columns (2048 px wide frame). Each channel has a slightly different DC
offset that can vary observation to observation depending on detector
temperature and sky background. When these offsets are large they produce a
visible column-banded gradient in reconstructed spatial maps (especially
noticeable for faint compact targets on a low sky background, as seen in the
May–Aug 2026 SPT2040 / XMM2215 data).

The inter-channel correction (`interchannel_correct = True`) is the intended
fix: it uses the inter-slice pixels (dead rows between IFU slices in the
raw frame) to measure and remove these per-channel DC offsets before
reconstruction.

The Jan–Feb 2026 data happened to have small enough channel offsets that
`interchannel_correct = False` produced clean maps. The May–Aug 2026 data
has larger offsets and requires the correction.

---

## Root Cause (three bugs)

### Bug 1 — `make_interchannel_ref` never called (`scripts/reduce_kmos.py`)

`interchannel_correct = True` requires a per-OB calibration file
`master_channel_YJYJYJ.fits` in `PROCDIR/<OB>/calib/`. This file is
generated by `make_interchannel_ref()` (defined in
`pyspark/calibration/output_channels.py`), but `reduce_kmos.py` never called
it. The calibration step ran darks/flats/arcs as usual, then `fix_detector_levels`
immediately tried to read a non-existent file.

### Bug 2 — `obsband` not passed to `fix_detector_levels` (`scripts/reduce_kmos.py`)

`run_params['detector']` only contains the keys from the `[detector]` config
section (`channel_correct`, `picture_correct`, `interchannel_correct`,
`prefix`). The call

```python
fix_detector_levels([...], subdir=folder, logger=dir_logger, **run_params['detector'])
```

never forwarded `obsband`. Inside `fix_detector_levels`, `obsband=None`, so
`get_interchannel_correct` looked for `master_channel_NoneNoneNone.fits`
instead of `master_channel_YJYJYJ.fits`.

### Bug 3 — Filename case mismatch (`pyspark/calibration/output_channels.py`)

`make_interchannel_ref` opened its two prerequisite calibration files with
**lowercase** names:

```python
fits.open(os.path.join(caldir, 'badpixel_dark.fits'))          # wrong
fits.open(os.path.join(caldir, 'master_flat_YJYJYJ.fits'))     # wrong
```

But `make_dark` and `make_flat` in `spark_calibs.py` move them to caldir with
**uppercase** names (`BADPIXEL_DARK.fits`, `MASTER_FLAT_YJYJYJ.fits`). On
Linux these are distinct filenames and the opens silently fail or raise
`FileNotFoundError`.

---

## The misleading `error: cannot open file [KMOS*.fits]`

This line in the main log is **not** the det-correction error. It comes from
`dfits KMOS*.fits` (invoked via `get_sof_list` in `fileutils.py`) running in
the rawdir root for a blank folder entry created by trailing commas in the
config's `subdirs` list. The blank-folder check immediately follows the failed
OB's `continue`, making the lines appear adjacent in the log.

---

## Fix

Three targeted changes, all in-repo:

### `scripts/reduce_kmos.py`

1. Import `make_interchannel_ref`:

```python
from pyspark.calibration import make_spark_calibs, make_interchannel_ref
```

2. Call `make_interchannel_ref` after calibrations succeed and before detector
   corrections, conditional on `interchannel_correct`:

```python
if run_params['detector'].get('interchannel_correct', False):
    master_logger.info('- Building interchannel reference')
    try:
        make_interchannel_ref(logger=dir_logger, subdir=folder, obsband=band,
                              outputdir=procdir)
    except Exception:
        break_check('interchannel reference', master_logger)
        continue
    master_logger.info('-- Finished interchannel reference')
    master_logger.info(' ')
```

3. Forward `obsband` to `fix_detector_levels`:

```python
fix_detector_levels([frame for frame, type in frames], subdir=folder,
        obsband=band, logger=dir_logger, **run_params['detector'])
```

### `pyspark/calibration/output_channels.py`

In `make_interchannel_ref`, fix both file opens to use uppercase names
matching what `spark_calibs.py` actually creates:

```python
with fits.open(os.path.join(caldir, 'BADPIXEL_DARK.fits')) as ffile:
```

```python
flat_file = fits.open(os.path.join(caldir, 'MASTER_FLAT_{0}{0}{0}.fits'.format(obsband.upper())))
```

## Deployment

After committing:

```bash
git pull                        # on hqempower1
# delete old PROCDIR for the new-data OBs (check mtimes first!)
# restart reduction with interchannel_correct = True in the cfg
export PYTHONPATH=. && nohup python scripts/reduce_kmos.py \
    -p scripts/kmos_server_new.cfg > reduction_new.log 2>&1 &
```

The `master_channel_YJYJYJ.fits` calibration step adds a few seconds per OB
(pure Python, no esorex call).
